# Spec: compile rules to ruff config

A one-way compiler from a pytest-imports rule dict to a set of nested
ruff configuration files, so that a subset of the architecture rules
also runs in the editor and in `ruff check`. The pytest suite remains
the source of truth; the compiled config is a fast, partial mirror.

Status: proposal. Not scheduled; written to pin down what is and is
not expressible before anyone starts on it.

## Motivation

pytest-imports rules run once per test session. Ruff runs on every
keystroke in most editors and in seconds on CI. For the rules that ruff
*can* express, getting a red squiggle at the offending import line is
strictly better feedback than a test failure after the fact.

Ruff resolves configuration per file: for each `.py` file it uses the
closest `.ruff.toml` / `ruff.toml` / `pyproject.toml` walking up from
the file's directory. That gives a natural encoding for scopes — a rule
scoped to a package becomes a config file placed in that package's
directory. Several of our predicates then map directly onto existing
ruff rules:

| ruff rule | setting |
| --- | --- |
| `TID251` banned-api | `[lint.flake8-tidy-imports.banned-api]` |
| `TID252` relative-imports | `lint.flake8-tidy-imports.ban-relative-imports` |
| `ICN001` unconventional-import-alias | `[lint.flake8-import-conventions.aliases]` |
| `PLC2701` import-private-name | `lint.extend-select` (preview) |

The compiler's job is to work out which of our rules land on those,
emit the files, and be explicit about the rest.

## Public API

```python
from pytest_imports.ruff import compile_to_ruff

def test_ruff_config_is_current(imports, imports_root_node):
    result = compile_to_ruff(RULES, imports_root_node)
    assert result.skipped == []
    assert result.matches_disk()
```

Signature:

```python
@dataclass(frozen=True)
class CompiledConfig:
    directory: Path          # package directory the file belongs in
    text: str                # full `.ruff.toml` content

@dataclass(frozen=True)
class Skipped:
    scope: Scope
    predicate: Predicate
    reason: str

@dataclass(frozen=True)
class CompileResult:
    configs: tuple[CompiledConfig, ...]
    skipped: tuple[Skipped, ...]

    def write(self) -> None: ...
    def matches_disk(self) -> bool: ...

def compile_to_ruff(
    rules: dict[Scope, Predicate | list[Predicate]],
    root_node: RootNode,
    *,
    extend: Path | None = None,
) -> CompileResult: ...
```

`extend` is the user's hand-maintained ruff config (typically the
project `pyproject.toml`); every emitted file carries an
`extend = "<relative path>"` pointing back to it so line length, rule
selection, etc. are inherited. When `None`, the nearest config above
the source root is located the same way ruff would.

The compiler is pure: it reads the model and returns text. `write()`
and `matches_disk()` are the only filesystem touch points, so the
"config is stale" test is a plain string comparison and can be run in
CI without write access.

The rule dict is the same object passed to `imports.check`; nothing
about the rules changes. Users keep one `RULES` dict and feed it to
both.

## Semantics

### Placement

Emitted files are always named `.ruff.toml` — the highest-precedence
name in a directory, and one unlikely to collide with a hand-written
`ruff.toml`. Each starts with a header comment identifying it as
generated by pytest-imports.

A file is emitted in a package directory exactly when the set of
compiled rules in effect there differs from the set in effect in the
parent directory. Because ruff does **not** merge nested configs —
each table (`banned-api`, `aliases`, …) is replaced wholesale by the
closest file — every emitted file contains the *full* effective set for
its subtree, not a delta. Concretely:

- `project()` rules go in the source root's file.
- `scope('a.b')` rules go in `a/b/.ruff.toml`, together with any
  `project()` and `scope('a')` rules that also cover `a.b`.
- `scope('a', without='b')` produces `a/.ruff.toml` carrying the rule,
  and `a/b/.ruff.toml` carrying everything in effect at `a` *except*
  that rule. If nothing is left, `a/b/.ruff.toml` is still emitted
  (with only `extend`) — the file is what stops the parent's bans from
  applying.

Every emitted file re-states `src` (as absolute-from-config relative
paths back to the configured source roots), because a nested config
otherwise moves ruff's project root and breaks first-party detection
for isort and friends in that subtree.

### Predicate mapping

The compiler must never **over-approximate** — a compiled ban that
flags code the pytest suite accepts would contradict the source of
truth and train people to ignore the squiggles. Under-approximation
(the compiled config misses some violations) is acceptable and is
reported per rule in `skipped` when a rule cannot be compiled at all.

| Rule | Compiles to | Fidelity |
| --- | --- | --- |
| `must_not_import('x.y')` | `banned-api."x.y"` | Exact. Both sides are prefix matches: our string target covers `x.y` and its descendants, and so does TID251. Note TID251 also flags attribute access `x.y.z` in the body, not just import statements — a stricter reading that we accept since it never passes an import we would flag. |
| `must_not_import(descendants('p'))` | one `banned-api` entry per submodule of `p` known to the model | Exact today; closed-world (see hazards). `p` itself is not banned, matching `Descendants` semantics. `without=` removes the excluded submodules from the list, recursing into a submodule only when an exclusion lies beneath it. |
| `must_not_import(internal())` | one `banned-api` entry per top-level module under the source roots | Exact today; closed-world. |
| `must_not_import(internal(), via='relative')` | `ban-relative-imports = "all"` | Exact. |
| `must_not_import(..., via='absolute')` and any other `via` combination | — | **Skipped.** TID251 resolves relative imports to qualified names, so it cannot distinguish the two forms. |
| `must_only_import(allowed, among=U)` | `banned-api` entries for the maximal subtrees of `U` not covered by `allowed` | Exact today; closed-world. Walk the model from the root of `U`; ban a node when neither it nor any descendant is allowed, otherwise recurse. **Skipped** when any `allowed` entry is a `descendants(...)` target, because TID251 cannot allow `p`'s children while banning `p` itself. |
| `must_not_import_private()` | `extend-select = ["PLC2701"]`, `preview = true` | Approximate. PLC2701 exempts imports within the same top-level package; ours does not. Under-approximates, so acceptable. |
| `must_not_import_private(path=...)` | — | **Skipped.** PLC2701 takes no target filter. |
| `must_alias('numpy', 'np')` | `aliases."numpy" = "np"` (ICN001) | Approximate. ICN001 covers clauses 2a and 2b of the `must_alias` spec (bare import, wrong alias). The "alias bound to a descendant" clause needs `banned-aliases` per descendant, which the model does not know for external packages — omitted. Star imports are left to `F403`, which is not enabled by the compiler. |
| `must_import(...)` | — | **Skipped.** An existence check across a scope; per-file linting cannot express it. |

### Scope mapping

| Scope | Compiles to |
| --- | --- |
| `project()` | file at each source root |
| `scope('a.b')` where `a.b` is a package | file in `a/b/` |
| `scope('a.b')` where `a.b` is a single `.py` module | **Skipped.** Config is per-directory. `per-file-ignores` can only disable a rule for the file, not drop one ban. |
| `scope('a', without='b')` where `a.b` is a package | files in `a/` and `a/b/` as described under *Placement* |
| `scope('a', without='b')` where `a.b` is a single module | **Skipped** for the same reason. |

Our own `test/arch/` rules are mostly module-scoped
(`scope('pytest_imports.model')` etc.), so this project would compile
almost nothing from them. That is the honest state of things, not a
reason to bend the mapping.

### Failure messages

Each `banned-api` entry carries a `msg` in the same shape as our failure
messages, so a ruff diagnostic reads like a pytest-imports failure:

```toml
[lint.flake8-tidy-imports.banned-api]
"myapp.db".msg = "pytest-imports: [scope myapp.api] must not import myapp.db"
```

When two rules ban the same path in the same directory, the first
rule's message wins and the second is dropped silently; TOML cannot
hold two entries with one key.

## Hazards

- **Closed world.** Every `descendants(...)`, `internal()` and
  `must_only_import` compilation enumerates the model at compile time.
  A package added later is not banned until the config is
  regenerated. The `matches_disk()` test is what turns that from a
  silent gap into a test failure.
- **Packaging.** `.ruff.toml` files inside package directories are
  picked up by sdist/wheel builds unless excluded. The README section
  for this feature should show the one-line `MANIFEST.in` /
  `[tool.hatch.build]` exclusion.
- **Preview.** `PLC2701` requires `preview = true`, which enables every
  other preview rule the user has selected. Emitted only when the rule
  dict contains `must_not_import_private()`; documented.
- **`extend` target must exist.** If the user has no ruff config at
  all, `extend` is omitted and the emitted files stand alone with ruff
  defaults.

## Required code changes

- New module `src/pytest_imports/ruff.py` holding everything above.
  It imports from `model` and `query` only; `query` does not import
  it. Add the corresponding `must_not_import` rules to `test/arch/`.
- `src/pytest_imports/__init__.py` — do **not** re-export; the feature
  is opt-in via `from pytest_imports.ruff import compile_to_ruff` so
  the core API surface stays unchanged.
- No changes to `model.py`, `parser.py`, or `query.py`. The compiler
  reuses `_match_target` for the `must_only_import` walk; promote it to
  a public helper on `query` (name TBD) rather than importing a
  private name across modules.

## Tests

- `test/unit/test_ruff.py` — one test per row of the two mapping
  tables, driven by a hand-built `RootNode`; assert the emitted TOML
  text and the `skipped` list. Cover the `without` placement case
  where the excluded subpackage gets an otherwise-empty file.
- `test/integration/` — a small tree on disk; compile, `write()`, then
  invoke `ruff check` as a subprocess on a file that violates each
  compiled rule and assert the expected rule code appears. This is the
  only test that depends on ruff's actual config-discovery behaviour
  and is the one that catches ruff upgrades changing the semantics.
- `test/integration/` — `matches_disk()` round-trip: write, assert
  true; touch a file, assert false.

## Docs

- `README.md` — new section *Running rules in ruff*, listing the two

- `AGENTS.md` — add `ruff.py` to the data-flow list.
- `GLOSSARY.md` — add **compiled config** (the emitted `.ruff.toml`

## Open questions / non-goals

- **Decompiling** ruff config back into rules is out of scope; the
  mapping loses intent (`internal()` becomes a list of names).
- **Replacing** the pytest suite is explicitly a non-goal. Even when
  every rule compiles, the closed-world caveat means the test is what
  guarantees the config still reflects the project.
- **`must_import`** could in principle be approximated by a custom
  ruff plugin once ruff supports them; not worth designing around now.
- Should `compile_to_ruff` be exposed as a CLI (`python -m
  pytest_imports.ruff`) so it can run without a test session? Probably
  yes eventually, but the fixture-based route is enough for a first
  cut and avoids inventing an argument parser for source-root
  discovery that `imports_project_paths` already does.
- Whether the compiler should also emit `F403` alongside `ICN001` to
  cover the star-import clause of `must_alias`. Leaning no: enabling a
  general-purpose rule project-wide on behalf of one alias rule is a
  surprising side effect.
